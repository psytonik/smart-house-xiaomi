# ADR 0016. Говорить в камеру из браузера

Дата: 2026-10-31. Статус: принято.

## Контекст

Звук с камеры идёт в браузер без проблем, а в обратную сторону первая версия не работала: кнопка «Talk» подключала микрофон к тому же WebRTC-соединению, что и видео. go2rtc получал звук (Opus 48 кГц), но камере его не отдавал: динамик камеры принимает только **A-law 16 кГц** (`PCMA/16000`), а go2rtc не перекодирует звук в эту сторону сам. Браузер умеет только PCMA 8 кГц, что тоже не совпадает. Проверено вживую: у камеры не появлялся отправитель (`senders: []`).

## Решение

Звук проходит через ffmpeg, который go2rtc запускает сам:

```
микрофон ──WebRTC (Opus)──> POST /api/talk ──> go2rtc: поток psytonik_base_talk
                                                      │  ffmpeg:psytonik_base_talk#audio=pcma/16000
                                                      ▼
                                           go2rtc: поток psytonik_base ──> динамик камеры
```

- Браузер при нажатии «Talk» открывает **отдельное** отправляющее WebRTC-соединение (просмотр остаётся только на приём) и шлёт предложение на `POST /api/talk`.
- Бэкенд (`Go2rtc.publishTalk`) публикует его в go2rtc (`/api/webrtc?dst=<поток>_talk`), потом (`bridgeTalk`) ждёт, пока поток микрофона придёт, и вызывает `POST /api/streams?dst=<поток>&src=ffmpeg:<поток>_talk#audio=pcma/16000`. Мост закрывается сам, когда браузер закрывает соединение.
- go2rtc пускает публикацию только в уже существующий поток, поэтому при первом разговоре бэкенд создаёт `<поток>_talk` с заглушкой `webrtc:`. go2rtc записывает его в `go2rtc.yaml` (одна строка), больше это не повторяется.
- **Источники не приходят из запроса.** Имена потоков и строка `ffmpeg:…` собираются на бэкенде, от клиента берётся только SDP. Иначе через `src` можно было бы запустить любую команду (`exec:`). Тест это проверяет.
- Микрофон закрывается сам через 60 секунд (`TALK_MAX_MS`), при остановке кнопкой, при смене режима и закрытии страницы. Пока вы говорите, звук камеры в браузере отключён, иначе будет эхо.
- Микрофон браузер даёт только на `localhost` или по HTTPS: по `http://10.0.0.8:3100` кнопка отключена с пояснением.

## Проверка

- Бэкенд (+8 тестов, `test/talk.test.ts`, на подставном go2rtc): токен, публикация, мост с точной строкой, ожидание потока, создание потока один раз, запрет брать имена и источники из запроса, отказ go2rtc, пустой и слишком большой запрос.
- Живая проверка на камере с беззвучным источником вместо микрофона: у камеры появился отправитель `pcm_alaw 16000`, ffmpeg кормит его непрерывно.
- **Не проверено:** слышен ли настоящий голос, громкость и задержка.

## Последствия

- Минус: задержка выше, чем у прямой связи (микрофон → go2rtc → ffmpeg → камера), порядка секунды.
- Минус: в `go2rtc.yaml` появилась одна служебная строка `psytonik_base_talk: webrtc:`.
- Плюс: звук в камеру не зависит от кодека, который выбрал браузер.

## Дополнение: причина шума в динамике и исправление go2rtc

Голос доходил до go2rtc чистым (спектрограмма записанного потока), а из динамика камеры шёл только шум, с любым кодеком (A-law 16 кГц, PCM, Opus). Причина нашлась в исходниках go2rtc 1.9.15, `pkg/xiaomi/miss/cs2/conn.go`, функция `WritePacket` (отправка пакета в камеру по cs2+udp):

```go
copy(req[offset:], hdr)
copy(req[offset+hdrSize:], hdr)   // второй раз копировался заголовок, а не звук
```

Камера получала заголовок дважды и нули вместо звука. Исправление в одну строку (`payload` вместо `hdr`) лежит в `cs2-write-payload.patch` и применяется в `./camera.sh build-motor` вместе с двумя прежними патчами. Проверено вживую: после правки фраза из синтезатора слышна из камеры чисто (формат A-law 16 кГц, без смены кодека).

Две ловушки, которые стоили времени:
- **Мосты копились.** Каждый разговор оставлял живой `ffmpeg` в go2rtc, и несколько мостов писали в один динамик. Теперь каждый разговор начинается с удаления старого потока, а «стоп» вызывает `DELETE /api/talk`.
- **Агент автозапуска перезапускает всё.** Пока launchd-агент `com.psytonik.xiaomi-camera` загружен, остановленные вручную go2rtc и бэкенд поднимаются снова, и тестовая сборка go2rtc не может занять порты. Для экспериментов агент выгружают: `launchctl bootout gui/$(id -u)/com.psytonik.xiaomi-camera`, потом возвращают `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.psytonik.xiaomi-camera.plist`.

Если голос идёт в камеру прямо из микрофона Mac, рядом стоящая камера и микрофон образуют обратную связь (свист или шипение), это не ошибка кода.
