# ADR 0021. Добавление устройств без приложений производителей

Дата: 2026-11-05. Статус: **обсуждается** (решение не принято, код не написан; продолжим дома, когда будет доступ к устройствам).

## Контекст

Сейчас каждое устройство прописано руками в `backend/.env` (`LIGHT_IP`, `VACUUM_IP`, `VACUUM_TOKEN`, `TV_IP`), у каждого типа свой модуль (`lights.ts`, `vacuum.ts`, `tv.ts`) и своя страница. Новую лампу, камеру или пылесос приходится сначала добавлять в приложении производителя (CozyLife, Yeelight, Mi Home): оно по QR-коду подключает устройство к Wi-Fi и привязывает к облачному аккаунту.

**Цель:** приложение само ищет устройство и подключается к нему, без CozyLife, Yeelight, Mi Home и т. п. Не зависеть от приложений и облаков производителей.

Что делает родное приложение (и что из этого нужно взять на себя):

1. Передаёт устройству имя и пароль Wi-Fi (provisioning). **Берём на себя.**
2. Привязывает устройство к облачному аккаунту. Нужно только производителю, нам нет.
3. Выдаёт ключ для локального управления (токен). **Берём на себя.**

Универсального способа нет: у каждого семейства устройств свой протокол настройки. Поэтому это набор плагинов, а не одна функция.

## Предлагаемое решение (черновик)

- **Реестр устройств** в одном файле (например, `data/devices.json`) вместо переменных `.env`: id, тип (`camera`, `vacuum`, `light`, `tv`), драйвер, адрес, секреты, название, комната.
- **Драйверы по типам** за общим интерфейсом. Это текущие `vacuum.ts`, `light.ts`, `tv.ts`; новый драйвер нужен только для нового класса устройств.
- **Плагины настройки по протоколам**, каждый умеет найти устройство в режиме настройки и передать ему Wi-Fi:
  - `matter`: открытый стандарт, QR на устройстве содержит код сопряжения; мы становимся контроллером;
  - `miio-ap`: устройство Xiaomi в режиме настройки поднимает свою точку Wi-Fi, по UDP 54321 ему можно отправить `miIO.config_router`, токен отдаётся при рукопожатии;
  - `tuya-ap` / EZ: режимы известны, ключ для локального управления обычно берут из облака Tuya;
  - `ble`: Bluetooth-ленты, Wi-Fi не нужен (уже работает через `tools/ble_helper.py`);
  - `lan`: устройство уже в сети, ищем по mDNS, UDP-broadcast, ARP, а у Xiaomi ещё по списку облака (`xiaomiCloud.ts` уже отдаёт `did`, `model`, `localip`, `token`).
- **Универсальный драйвер по MIoT-Spec** для устройств Xiaomi: свойства и действия берутся из спецификации модели (см. раздел ниже), код под каждую модель не нужен.
- **Страницы и голосовой помощник строятся из реестра:** вторая лампа появляется в интерфейсе и в «включи свет» сама, различается по названию и комнате.
- **Роль QR:** у Matter QR содержит всё для сопряжения. У остальных QR только называет модель и серийный номер и подсказывает, какой плагин запускать. Сканировать в браузере телефона можно только по HTTPS.
- **Физическое ограничение:** чтобы передать устройству Wi-Fi, Mac или телефон на 20–30 секунд подключается к временной сети устройства и теряет интернет. Для Bluetooth-настройки нужен Bluetooth. Удобнее с телефона (Expo-приложение, Шаг 1 в `ROADMAP.md`).

## Что возможно по семействам

**Это оценка по памяти о публичных реверсах, на устройствах не проверялось.**

| Семейство | Без родного приложения | Комментарий |
|---|---|---|
| Matter | да, штатно | любой бренд с логотипом Matter |
| Xiaomi miio, старые прошивки | скорее да | `config_router` по AP-режиму |
| Xiaomi, новые прошивки (Dreame) | под вопросом | нужен эксперимент на DreameBot L10 Plus |
| Tuya-клоны | частично | ключ часто через облако Tuya |
| CozyLife, Yeelight | неизвестно | смотреть трафик их приложения (инструменты REA) |
| Bluetooth-ленты | уже да | |
| Камера Xiaomi | тяжело | видео идёт напрямую по локальной сети (CS2 P2P через go2rtc), облако нужно для входа и ключей (оценка по исходникам go2rtc, не проверено, какие запросы уходят при каждом подключении). Своё облако вряд ли получится: адреса прошиты. Варианты: кэшировать ключи сессии, альтернативная прошивка (для 029a02 ничего не известно), камера с RTSP или ONVIF |

## Что дало изучение чужих проектов

### hass-xiaomi-miot (al-one, Apache-2.0, v1.1.5; изучали 2026-11-05, читали код, не запускали)

Интеграция Home Assistant для Xiaomi. Целиком не подходит (Python, облако по умолчанию, `iot_class: cloud_polling`), но полезны идеи:

1. **Универсальный драйвер по MIoT-Spec.** Описание модели берётся с `miot-spec.org`: `GET /miot-spec-v2/instances?status=all` даёт соответствие «модель → type» (кэш 7 дней), `GET /miot-spec-v2/instance?type=<type>` даёт сервисы, свойства (`siid`/`piid`, формат, доступ чтение/запись, `value-list`, `value-range`, единицы) и действия (`aiid`). Запасной хост `spec.miot-spec.com`, 3 попытки, кэш на диске 30–50 дней. По описанию строится управление без отдельного кода под модель: лампа, розетка, увлажнитель и т. д. Это основа для драйвера «Xiaomi по спецификации» в реестре устройств.
2. **Локальный miot по UDP 54321**: `get_properties` / `set_properties` с `{did, siid, piid[, value]}`, действия с `{did, siid, aiid, in}`. Их `core/mini_miio.py` (около 350 строк) делает то же, что наш `backend/src/miio.ts`.
3. **Список моделей, работающих по локальной сети** (`MIOT_LOCAL_MODELS`). `dreame.vacuum.p2028a` (наш пылесос) в нём есть. Камеры `chuangmi.camera.029a02` нет: её интеграция берёт только через облако.
4. **Вход в облако** (`core/xiaomi_cloud.py`): капча, подтверждение по тикету, `ssecurity`, регионы; список устройств через `home/device_list` и постранично `v2/home/home_device_list` (`limit` 300, `start_did`, `has_more`). Наш `tools/xiaomi-cloud.ts` уже умеет 2FA и капчу.

**Чего там нет:** настройки Wi-Fi устройства и поиска в режиме настройки (`config_router`, mDNS, broadcast не найдены). Главную задачу «обойти Mi Home» репозиторий не решает: устройства сначала добавляются в Mi Home.

**Сравнение с нашим кодом:**

| Тема | У нас | У них | Вывод |
|---|---|---|---|
| Локальный miio | `miio.ts`, очередь вызовов, проверка подписи ответа | `mini_miio.py`, подпись ответа не проверяется | наш не хуже |
| Много свойств за раз | один запрос | пачки по 15 (запрос меньше 1024 байт, ответ до 1056) | взять пачки по 15 |
| Потеря пакета | один запрос | до 3 попыток с новым hello | взять повторы |
| Описание устройства | отдельный код на тип | MIoT-Spec | взять |
| Вход в облако | есть, с 2FA и капчей | есть | сверить детали, если вход сломается |
| Список устройств | `listDevices` | `home/device_list` + постраничный `home_device_list` | проверить, видим ли общие дома |

## Предлагаемый порядок работ

1. Реестр устройств и перенос текущих (лампа, пылесос, телевизор, камера) из `.env`, поиск `lan`.
2. Плагин Matter.
3. Эксперимент с `miio-ap` на пылесосе.
4. Остальные семейства по мере покупки устройств.

## Последствия (если примем)

- `.env` перестаёт быть местом для адресов устройств, остаётся реестр; нужна миграция текущих настроек.
- Секреты (токены, ключи) живут в реестре: файл не коммитить, права доступа как у `.env`.
- Обход облака производителя может сломаться с обновлением прошивки; для каждого плагина нужен запасной путь (добавить в родном приложении, найти через `lan`).
