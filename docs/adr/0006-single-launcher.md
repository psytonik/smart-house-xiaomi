# ADR 0006. Один файл для запуска всего приложения

Дата: 2026-10-30. Статус: принято.

## Контекст

Чтобы запустить приложение, нужно было открыть несколько терминалов: `start-motor.sh` (go2rtc), `npm run dev` в `backend/` (бэкенд, в режиме watch), иногда `web/` для сборки и отдельные `motor.sh` и `build-motor.sh`. Забытый терминал означал «камера не работает», а закрытый останавливал сервис без предупреждения.

## Решение

Один файл `camera.sh` в корне проекта.

- **Команды:** запуск с логами (по умолчанию), `up`, `stop`, `restart`, `status`, `logs`, а также `motor` и `build-motor`: логика `motor.sh` и `build-motor.sh` перенесена внутрь.
- **Проверки до запуска** с понятными сообщениями: версия Node, наличие `go2rtc-motor`, `go2rtc.yaml`, `backend/.env` и `API_TOKEN` (значение нигде не печатается). Если нет `ffmpeg`, предупреждает, не останавливаясь. Если нет `node_modules` или собранного веб-приложения, делает `npm install` и сборку.
- **Готовность:** ждёт ответа go2rtc (до 20 с) и `/health` бэкенда (до 30 с). Если процесс сразу завершился, показывает последние строки лога.
- **Повторный запуск безопасен.** Если go2rtc или бэкенд уже отвечают, скрипт использует их и **не останавливает**: останавливается только то, что запустил он сам (по pid-файлам в `.run/`). Если порт занят чужой программой, он отказывается запускаться и говорит об этом.
- **Остановка:** сначала бэкенд (он закрывается через go2rtc), потом go2rtc. Мягкий сигнал, через 10 с принудительно. Бэкенд запускается как `tsx` без режима watch; процессы-потомки останавливаются вместе с ним.
- **Логи** пишутся в `logs/` (ротация при 10 МБ), pid-файлы в `.run/`; обе папки в `.gitignore`.
- Совместимость с bash 3.2 из macOS, без дополнительных зависимостей.
- Адрес go2rtc можно переопределить переменной `GO2RTC_API`. Это нужно для проверки скрипта в изолированной копии.

Режим watch не используется намеренно: перезапуск при правках удобен при разработке (`npm run dev` в `backend/` по-прежнему доступен), но для постоянной работы он лишний и мешает остановке.

## Проверка

Скрипт проверен в изолированной копии проекта на других портах с подставным go2rtc, чтобы не задеть работающее приложение: запуск, повторный запуск, перезапуск, остановка (порты освобождаются, pid-файлов не остаётся), запуск с логами и остановка сигналом, понятные ошибки без `.env` и без `go2rtc-motor`, повторный запуск при уже работающем приложении (ничего не делает, ничего не останавливает). Не проверено: запуск с настоящей камерой и сборка `build-motor` (нужны Go и сеть).

## Последствия

- Старые `start.sh`, `start-motor.sh`, `motor.sh` и `build-motor.sh` удалены, как и обычная сборка `go2rtc` без поворота камеры с архивом, из которого она взята: `camera.sh` использует только `go2rtc-motor`, а при необходимости собирает его заново (`./camera.sh build-motor`).
- Автозапуск при входе в систему (launchd) теперь сводится к одной команде `camera.sh up`; сам автозапуск пока не настроен.
- Если процесс упадёт в фоновом режиме (`up`), скрипт этого не заметит, пока не запустите `status`. Постоянное наблюдение и перезапуск — задача launchd.
