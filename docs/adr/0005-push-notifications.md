# ADR 0005. Пуш-уведомления о новых клипах через Expo Push

Дата: 2026-10-30. Статус: принято (сервер). Доставка на настоящий телефон ещё не проверена.

## Контекст

Бэкенд записывает клипы по движению, но узнать о них можно только открыв веб-приложение. Роадмап (Шаг 1) предполагает мобильное приложение на Expo, которому нужны пуши. Бэкенд закрыт токеном и стоит дома, поэтому отправка уведомлений требует внешнего сервиса: ни Apple, ни Google не принимают пуши напрямую от домашнего сервера.

## Решение

### Модуль `src/push.ts`

`PushService` хранит токены телефонов, подписывается на событие `clip` рекордера и отправляет сообщения в Expo Push API (`POST https://exp.host/--/api/v2/push/send`). Модуль самостоятельный: сеть, часы и таймеры передаются снаружи, поэтому логика проверяется без настоящего Expo.

- **Регистрация.** `POST /api/push/register` с токеном вида `ExponentPushToken[...]`. Формат проверяется строго, повтор безопасен, лимит 20 устройств. `unregister` удаляет. `GET /api/push` показывает число устройств. `POST /api/push/test` отправляет тестовое сообщение и отвечает `409`, если устройств нет, чтобы не создавать иллюзию, что всё работает.
- **Хранение.** `data/push-devices.json` с правами `600`, запись через временный файл и `rename`, чтобы сбой не оставил половину файла. Каталог `data/` в `.gitignore`.
- **Сообщение.** Заголовок «Motion detected», текст «14:32 · 12 s», в `data` идентификатор клипа и тип, по которым приложение откроет нужный клип. Звук по умолчанию, высокий приоритет, канал Android `motion`.
- **Мёртвые токены.** Ответ `DeviceNotRegistered` на отдельное сообщение удаляет токен. Остальные ошибки пишутся в лог.
- **Отказоустойчивость.** Обработчик события `clip` не бросает исключений (иначе необработанный отказ положил бы процесс, а клип уже записан). Недоступность Expo или таймаут 10 секунд только логируются.

### Ограничение частоты

Первый клип отправляется сразу. Клипы в течение `PUSH_MIN_INTERVAL_SEC` (120 с) после последнего уведомления копятся и уходят одним сообщением «N more events, last at HH:MM», которое открывает самый новый клип, когда интервал закончился. Один таймер на весь интервал, никаких очередей. `0` отключает ограничение. Тестовые уведомления ограничение не затрагивают. При остановке сервера отложенная сводка отбрасывается.

Почему не просто «не чаще раза в 2 минуты»: так пропадали бы события. Сводка сохраняет сам факт, что движение было, и количество.

## Что уходит за пределы дома

| Данные | Куда | Зачем |
|--------|------|-------|
| Токен телефона | серверы Expo, затем Apple или Google | адрес доставки |
| Заголовок, время начала, длительность | то же | текст уведомления |
| Идентификатор клипа | то же | открыть клип в приложении |

Видео, снимки и токен API наружу не уходят. Картинку в уведомлении мы не отправляем сознательно: Expo может показать её только по публичному адресу, а бэкенд закрыт и будет закрыт даже при доступе через Tailscale. Сам факт и время движения дома всё-таки видят Expo и Apple или Google. Пока ни один телефон не зарегистрирован, из дома не уходит ничего.

`EXPO_ACCESS_TOKEN` нужен только если для проекта Expo включена «улучшенная защита пушей». Это секрет: хранится только в `.env`, в логи не пишется.

## Проверка

- `test/push.test.ts`: регистрация, формат токена, лимит устройств, сохранение между запусками, содержимое сообщения, заголовок авторизации Expo, ограничение частоты по шагам (сразу, удержание, сводка, следующий клип), отключение ограничения, `DeviceNotRegistered`, сбой сети без исключения, тест без ограничения, подписка на `clip` и отмена сводки при остановке.
- `test/push-api.test.ts`: маршруты за токеном API, проверка тела запроса, `409` без устройств, права `600` на файле токенов, реальный HTTP-запрос к заглушке Expo.
- Настоящий Expo, Apple и Google не использовались: ни одного реального уведомления не отправлено.

## Последствия

- Минус: доставка зависит от Expo. Если сервис недоступен, пуши не приходят, но запись и веб-приложение работают.
- Минус: сводка приходит с задержкой до интервала. Для срочности можно поставить `PUSH_MIN_INTERVAL_SEC` меньше или `0`.
- Минус: нет проверки квитанций доставки Expo (receipts) — только быстрый ответ с билетами. Для одного владельца и 1–2 телефонов этого достаточно. При росте нужна отдельная проверка квитанций через несколько минут.
- Альтернатива, не выбранная сейчас: PWA с Web Push (VAPID) вместо Expo. Не требует аккаунта Apple Developer и внешнего посредника, но нужен HTTPS (`tailscale serve`) и установленное на экран «Домой» веб-приложение. Решение между Expo и PWA принимается при Шаге 2; серверная часть для PWA потребует другого транспорта в `PushService`, регистрация и ограничение частоты остаются.
