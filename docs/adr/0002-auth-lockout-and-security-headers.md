# ADR 0002. Блокировка подбора токена и заголовки безопасности

Дата: 2026-10-30. Статус: принято.

## Контекст

После [ADR 0001](0001-signed-media-urls.md) токен принимается только в заголовке `Authorization`. Оставались два пробела:

1. Ничто не мешало перебирать токен: сколько угодно попыток с одного адреса.
2. Бэкенд отдаёт веб-приложение без заголовков безопасности: нет CSP (любой внедрённый скрипт получил бы доступ к токену в `localStorage`), нет `Referrer-Policy` (подписанные ссылки могли уходить в `Referer`).

## Решение

### Блокировка по адресу (`src/authLimiter.ts`)

Свой небольшой лимитер вместо `@fastify/rate-limit`. Библиотека считает **все** запросы, а интерфейс легально делает много запросов: опрос статуса каждые 5 секунд, удержание кнопки PTZ каждые 450 мс, десятки превью. Лимит на все запросы либо мешал бы работе, либо был бы слишком мягким, чтобы остановить подбор.

- Считаются только **неверные токены**: запрос с заголовком `Authorization: Bearer …`, который не совпал.
- Запрос без учётных данных (протухшая подписанная ссылка, вкладка после выхода) не считается попыткой подбора и не блокирует адрес.
- После `AUTH_MAX_FAILURES` (10) неверных токенов за `AUTH_WINDOW_SEC` (60 с) адрес получает `429` с `Retry-After`. Проверка идёт до сравнения токена, поэтому верный токен с заблокированного адреса тоже получает `429`.
- Верный токен сбрасывает счётчик адреса. Состояние хранится в памяти, перезапуск его сбрасывает. Число отслеживаемых адресов ограничено (10 000).
- Подписанные ссылки лимитом не затрагиваются: подпись HMAC-SHA256 не подобрать.
- Адрес берётся из `req.ip` (адрес сокета). Если перед бэкендом появится reverse proxy, нужно включить `trustProxy`, иначе все клиенты будут выглядеть как один адрес.

### Заголовки (`@fastify/helmet`)

CSP описывает то, что приложение реально загружает: свои скрипты и стили, `blob:` для режима Frames и MediaSource в HLS, `data:` для иконки, `frame-ancestors 'none'`, `object-src 'none'`. Нет `unsafe-inline`. Дополнительно: `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff` и остальные значения по умолчанию.

Отключены:
- `upgrade-insecure-requests`: сломал бы доступ по `http://<ip>:3100` в домашней сети.
- `Strict-Transport-Security`: без TLS он бессмыслен, а браузер, увидев его на HTTPS позже, закрепил бы его на хосте.

## Проверка

- `test/security.test.ts`: лимитер (окно, сброс, раздельные адреса, потолок памяти); блокировка и `Retry-After` в приложении; запросы без токена не считаются; заголовки.
- Тест читает собранный `public/index.html` и падает, если в нём появятся инлайновые скрипты, стили или обработчики, которые CSP заблокировал бы.
- Проверено в Chrome на собранном приложении: интерфейс, шрифт и стили загружаются, переключение WebRTC, HLS и Frames не вызывает нарушений CSP. Живая камера при этой проверке не была подключена.

## Последствия

- Минус: пользователь, ошибившийся с токеном 10 раз, ждёт до минуты. Для одного владельца это приемлемо.
- Минус: если позже понадобится подгружать что-то с другого домена (шрифты, аналитика, TURN по HTTP), CSP придётся расширять осознанно.
- Не сделано: логирование блокировок и оповещение. Фастифай уже пишет 429 в лог запросов.
