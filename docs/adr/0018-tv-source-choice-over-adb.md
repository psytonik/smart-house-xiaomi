# ADR 0018. Меню источников и приложения телевизора через ADB

Дата: 2026-10-31. Статус: принято.

## Контекст

Кнопка «Input» должна открывать «Source Choice» (Home, TV, HDMI 1, HDMI 2, AV, Media Player), как у физического пульта. Через протокол Android TV Remote это не работает: коды `TV_INPUT` (178), `TV_INPUT_HDMI_1…4` (243-246), AV (247) и около десяти других кодов (долгое нажатие, Settings, Menu, Guide, Info, TV, контекстные меню и др.) телевизор принимает и ничего не делает: меню слушает только ИК-пульт.

На телевизоре при этом открыт порт ADB 5555, `adb` есть на Mac. Google Play на этой прошивке отключён (`com.android.vending` в списке отключённых), другого магазина нет.

## Решение

Системный `adb` с фиксированными командами (`backend/src/tvAdb.ts`), включается переменной `TV_ADB=адрес:5555`:

- **Input:** `input keyevent 178`. Проверено: после команды окно `com.tcl.tv` получает фокус (это и есть «Source Choice»).
- **Источники:** список определяется у самого телевизора (`dumpsys tv_input`: аппаратные входы и их идентификаторы), кэш на 10 минут. HDMI и AV: `am start -a android.intent.action.VIEW -d content://android.media.tv/passthrough/<id входа>`, TV кнопкой 170, Home кнопкой 3, Media Player через `am start -n com.tcl.ui_mediaCenter/.main.MainActivity`.
- **Приложения без ссылки** (Prisma): запуск по компоненту лаунчера `am start -n top.rootu.prisma/.ConnectActivity`; такие приложения показываются, только когда настроен ADB. «Приложение не установлено» отвечает 404.
- **Запущенные приложения:** `ps` плюс список приложений с лаунчером; закрывать можно (`am force-stop`) только то, что человек открывал, и три служебных, которые запускаются снова сами (приёмник Chromecast, установщик пакетов, окно разрешений). Не закрываются никогда: `com.android.*`, `com.tcl.*`, `com.gathin.*` (лаунчер), сервисы Google (в том числе служба, с которой говорит наш пульт), клавиатуры. Решает сервер по тому, что реально запущено, а не запрос.
- **Безопасность команд:** команды собираются из констант и идентификаторов, найденных у телевизора, и проверяются регулярными выражениями; из запросов в оболочку телевизора ничего не попадает текстом. Адрес цели проверяется (`адрес[:порт]`).
- Приложения ставятся вручную через `adb install` (с APKMirror или из файлов пользователя), подпись проверяет Android (для набора частей требует одинаковую подпись). Файл с несошедшейся подписью не ставится и не переподписывается.

## Проверка

- Тесты с поддельным `adb`-скриптом (настоящий `execFile`) и дампом с реального телевизора: определение источников, команды переключения, повторное подключение, отказ на чужой источник и чужую цель, список и закрытие приложений.
- Живая проверка: «Input» открывает «Source Choice» (фокус у `com.tcl.tv`, «Назад» возвращает), переключение на HDMI 1, HDMI 2, AV и TV подтверждено пользователем на экране, Prisma открывается кнопкой.
- **Не проверено:** стрелки и OK внутри «Source Choice» через сетевой пульт; кнопка «Close» для каждого приложения.

## Последствия

- **Минус: ADB даёт этому Mac полный доступ к телевизору в домашней сети.** Без `TV_ADB` ничего этого не включается, а клавиши пульта продолжают работать.
- Минус: зависимость от `adb` (его путь ищется среди типичных мест, у launchd нет PATH оболочки; `TV_ADB_PATH` задаёт путь).
- Минус: идентификаторы входов и пакеты привязаны к этой прошивке; список источников поэтому определяется у телевизора, а не зашит.
- Плюс: работает с меню, которое иначе недоступно по сети, и даёт список приложений, которого в протоколе пульта нет.
