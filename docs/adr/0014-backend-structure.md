# ADR 0014. Структура бэкенда: корень сборки, модули маршрутов, сборщик клипов

Дата: 2026-10-30. Статус: принято.

## Контекст

К 13-му ADR почти всё приложение жило в двух файлах: `app.ts` (449 строк: создание сервисов, заголовки безопасности, проверка токена, 40 маршрутов) и `recorder.ts` (471 строка: процесс ffmpeg, анализ кадров, склейка клипов, чистка диска). Это уже один раз сыграло против нас: при правке одного файла легко затереть чужие изменения, а добавление настройки в `Config` ломало пять тестов, каждый из которых собирал `Config` вручную.

## Решение

Поведение и API не менялись, все тесты остались прежними.

- **`context.ts`** создаёт и запускает сервисы в нужном порядке и отдаёт `AppContext`. Это единственное место, где что-то строится через `new`.
- **`security.ts`**: заголовки (CSP) и проверка токена, подписанные ссылки, блокировка подбора.
- **`routes/*.ts`**: по модулю на область (`status`, `ptz`, `snapshots`, `events`, `zones`, `push`, `cameras`, `lamp`, `live`). Модуль берёт из `AppContext` только нужное и сам ничего не создаёт.
- **`app.ts`** (47 строк): корень сборки. Контекст, безопасность, обработка ошибок, подключение маршрутов, статика.
- **`clips.ts`** (`ClipBuilder`): склейка сегментов в mp4, превью, распознавание, отбраковка пустых. Рекордер остаётся владельцем процесса ffmpeg, трекера движения и учёта диска и вызывает `ClipBuilder` по окончании события.
- **`test/helpers.ts`** (`testConfig`): полный тестовый `Config`; тест называет только отличия.
- Из веба убран мёртвый код одиночной лампы (`Light.tsx`, `getLight`, `setLight`): блок «Lights» работает через `/api/lights`.

Проверка: `app.ts` 449 → 47 строк, `recorder.ts` 471 → 381; все 21 набор тестов бэкенда и 64 теста веба проходят.

## Что сознательно не делалось

- **Несколько камер.** Рекордер, зоны, клипы, детектор и пуши по-прежнему привязаны к одному `STREAM_NAME`. Это самое крупное архитектурное ограничение. Следующий шаг: `Camera` как сущность (свой рекордер, зоны, каталог `data/<camera>/`), `cameraId` в API и переключатель в вебе, с миграцией существующих клипов. Отдельная работа и отдельный ADR.
- **`/api/light`** (одна лампа CozyLife) дублирует `/api/lights/wifi`. Остался, потому что на него опираются тесты `light.test.ts`; убрать вместе с ними.
- **`recorder.ts`** всё ещё держит и процесс ffmpeg, и учёт диска. Если вырастет, вынести `FrameSource` (процесс и кадры) отдельно.
- **`App.tsx`** (около 290 строк) держит всё состояние монитора. Опросы можно вынести в хуки, но пока читается нормально.

## Последствия

- Плюс: правка одной области (например, зон) теперь затрагивает один небольшой файл, и тесты ловят поломку рядом.
- Плюс: новая настройка в `Config` требует одной правки в `test/helpers.ts`.
- Минус: больше файлов; маршруты получают весь `AppContext`, а не узкий интерфейс. Для проекта такого размера это приемлемо.
