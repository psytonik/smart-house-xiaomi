# ADR 0009. Панель «System»: состояние приложения простыми словами

Дата: 2026-10-30. Статус: принято (идея из [исследования camera.ui](../research/cameraui.md): у них есть логи и метрики в приложении).

## Контекст

Чтобы понять, почему нет клипов или картинка рассыпается, приходилось читать два лога и опрашивать API вручную (так найдены потери пакетов и залипшая запись в [ADR 0007](0007-damaged-stream-and-frozen-stream.md)). Видно это должно быть сразу в приложении.

## Решение

### Бэкенд

- `GET /api/system` (за токеном) собирает: достижимость go2rtc, состояние конвейера видео, диск, хранилище клипов, число телефонов для пушей и время работы.
- `src/health.ts` содержит чистую функцию `assess`: из чисел делает проверки с уровнем `ok`, `info`, `warn` или `error`, коротким заголовком и подсказкой, что делать. Общий уровень равен худшему из `warn` и `error`; `info` его не ухудшает.
- Проверки: **go2rtc** (недоступен: ошибка), **картинка** (ffmpeg не найден: ошибка; переподключение, нет кадров больше 10 с, повреждённая картинка: предупреждение; запись выключена или подключение: справка), **диск** (меньше 5 ГБ: предупреждение, меньше 1 ГБ: ошибка), **хранилище клипов** (почти заполнено: справка, потому что старые удаляются сами), **пуши**.
- Рекордер считает для этого: предупреждения декодера по секундам за последнюю минуту, число перезапусков ffmpeg и из них вызванных замерзанием, возраст последнего кадра.
- **Первые 20 секунд после запуска ffmpeg предупреждения декодера не считаются повреждением** (`startupGraceSec`). Живая проверка показала: сразу после перезапуска было 118 «предупреждений», а через минуту картинка в порядке. Декодер просто ждёт ключевой кадр. Движение в эти секунды по-прежнему подавляется.

### Веб-приложение

Раздел «System» (`SystemPanel`): итог («Everything is working», «Needs attention», «There is a problem»), время работы и список проверок, проблемы сверху. Уровень выражен **словом** (OK, Note, Warning, Problem), а не только цветом. Обновляется раз в 10 секунд; при сбое обновления остаётся последний ответ с пометкой, при истёкшем входе вызывается выход.

## Проверка

- Бэкенд: тесты `assess` на каждое правило и граничные значения, счётчики рекордера на подставном ffmpeg (предупреждения учитываются, перезапуски и замерзания считаются, стартовая пауза не засчитывается), эндпоинт.
- Фронтенд (+6 тестов): итог, подписи, порядок, время работы, сбой обновления, истёкший вход.
- Живое приложение: сразу после перезапуска панель показывала предупреждение о повреждённой картинке, а через минуту «Picture is flowing». Это и привело к стартовой паузе.
- Не проверено: вид панели в браузере на большом экране и телефоне.

## Последствия

- Минус: потери пакетов видны только косвенно, по предупреждениям декодера. Строки go2rtc `pop buffer is full` бэкенд не читает: это отдельный процесс, а логи пишет `camera.sh`.
- Минус: «нет кадров» определяется порогом 10 секунд, жёстко. Перезапуск при замерзании идёт отдельно, по `MOTION_STALL_SEC`.
