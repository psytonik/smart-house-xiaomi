# Телевизор TCL (Google TV): пульт на `/tv`

Страница `/tv` управляет телевизором по локальной сети: пульт, выбор источника, приложения, запущенные приложения. Облако не нужно. Телевизор у нас TCL «Smart TV» (Android 11, 32-битный ARM, лаунчер `com.gathin.tvhome`, региональная прошивка), адрес `10.0.0.9`.

Решения и почему так: [ADR 0017](adr/0017-tv-remote-own-client.md) (свой клиент протокола пульта) и [ADR 0018](adr/0018-tv-source-choice-over-adb.md) (меню источников и приложения через ADB).

## Настройка

В `backend/.env`:

| Переменная | Смысл |
|------------|-------|
| `TV_IP` | адрес телевизора (закрепите его в роутере). Без него страница пишет, как настроить |
| `TV_ADB` | `адрес:5555`: включает меню источников, выбор источника, запуск приложений вроде Prisma и список запущенных приложений. Без него работают только клавиши пульта |
| `TV_ADB_PATH` | путь к `adb`, если он не в `/opt/homebrew/bin`, `/usr/local/bin` или `~/Library/Android/sdk/platform-tools` (у launchd нет PATH оболочки) |
| `TV_REMOTE_PORT`, `TV_PAIRING_PORT` | `6466` и `6467`; меняются только в тестах |

### Сопряжение (один раз)

1. Включите телевизор.
2. Откройте `/tv`, нажмите «Show the code on the TV»: телевизор покажет код из шести символов (цифры и буквы A-F).
3. Введите код и нажмите «Pair». Опечатка в первом символе ловится до отправки на телевизор; можно ввести ещё раз.

Дальше ключ приложения лежит в `backend/data/tv-client.key` и `tv-client.crt` (режим 600, делает `openssl`), а факт сопряжения в `backend/data/tv.json`. «Pair again» на странице запускает сопряжение заново (после сброса телевизора).

### Отладка по сети (ADB)

Нужна для `TV_ADB`. На телевизоре: Настройки, «Настройки устройства», «О системе», семь раз нажать «Сборка», затем «Для разработчиков», включить отладку по сети; при первом подключении подтвердить запрос для этого Mac. На Mac нужен `adb` (`brew install android-platform-tools`). Проверка: `adb connect 10.0.0.9:5555`, затем `adb devices` должен показать `device`.

**ADB даёт этому компьютеру полный доступ к телевизору в домашней сети.** Не хотите держать его включённым: уберите `TV_ADB` из `.env`, остальное продолжит работать.

## Что есть на странице

- **Статус:** «Connected», приложение на экране («Now: …»), громкость или «Muted», экран включён или выключен. Данные приходят от телевизора сами; если он не отвечает (выключен или в глубоком сне), страница пишет «Not answering» и подключается заново сама (через 2, 5, 10, 30 секунд).
- **Питание:** кнопка On/Off (переключатель, состояние экрана читается у телевизора).
- **Пульт:** Back, Home, **Input** (открывает собственное меню «Source Choice» телевизора, через ADB), стрелки с OK (удержание повторяет), громкость, каналы, Guide, перемотка и воспроизведение.
- **Sources** (с ADB): Home, TV, HDMI 1, HDMI 2, AV, Media Player. Список берётся у самого телевизора и совпадает с его «Source Choice».
- **Running apps** (с ADB): что открыто в памяти телевизора с размером; «Close» у каждого и «Close all». Закрывается только то, что открывал человек, и три служебных (приёмник Chromecast, установщик пакетов, окно разрешений). Система, TCL, лаунчер, сервисы Google и служба, с которой говорит этот пульт, не закрываются никогда; защита проверяется на сервере.
- **Apps:** YouTube, Netflix, Prime Video, Disney+, Twitch (по ссылке, через пульт) и Prisma (через ADB, как обычное приложение).
- **More keys:** цифры, цветные клавиши, Info, Menu, Settings, Search, Subtitles, Live TV. Ряд HDMI-клавиш показывается только без ADB: на этом телевизоре они ничего не делают.
- **Клавиатура:** стрелки, Enter = OK, Esc или Backspace = Back, `+` и `-` громкость, `M` без звука.

## API

Все маршруты требуют токен приложения.

| Метод | Путь | Что делает |
|-------|------|------------|
| GET | `/api/tv` | `configured`, `paired`, `link` (`offline`, `connecting`, `ready`), `waitingForCode`, `powered`, `volume {level,max,muted}`, `app`, `apps`, `adb` |
| POST | `/api/tv/pair` | телевизор показывает код |
| POST | `/api/tv/pair/code` | `{code}`; 400 при неверном коде, 409 если сопряжение не начато |
| POST | `/api/tv/pair/cancel` | бросить сопряжение |
| POST | `/api/tv/key` | `{key}` из фиксированного списка (`up`, `ok`, `volumeUp`, `power`, `hdmi1`, `0`…`9` и др.); `input` идёт через ADB, если он настроен; 503, если телевизор не отвечает |
| POST | `/api/tv/app` | `{app}`: `youtube`, `netflix`, `prime`, `disney`, `twitch`, `prisma`; приложения «по компоненту» (Prisma) только с ADB |
| GET | `/api/tv/sources` | источники телевизора (нужен ADB) |
| POST | `/api/tv/source` | `{source}`: `home`, `tv`, `hdmi1`, `hdmi2`, `av`, `media` (что есть у телевизора) |
| GET | `/api/tv/running` | запущенные приложения, которые можно закрыть (нужен ADB) |
| POST | `/api/tv/running/close` | `{packages: [...]}` или `{all: true}`; закрывается только разрешённое и запущенное, ответ `{closed: [...]}` |

Ничего из запросов не попадает в команды телевизора текстом: клавиши, приложения и источники выбираются из фиксированных списков, пакеты для закрытия сверяются с тем, что реально запущено.

## Перезапуск после правок

Запущенный сервер не знает о новых маршрутах, пока его не перезапустить, ответ 404. Рабочий способ при включённом launchd-агенте:

```
launchctl kickstart -k gui/$(id -u)/com.psytonik.xiaomi-camera
```

Камера и go2rtc при этом переподключаются примерно на минуту. `./camera.sh restart backend` при загруженном агенте конфликтует с ним (новый сервер падает: порт 3100 занят, и launchd поднимает всё заново).

## Особенности этого телевизора

- Сетевой пульт Google TV **не открывает собственное меню «Source Choice»** и не переключает входы: коды `TV_INPUT` (178), HDMI (243-246), AV (247) и около десяти других кодов проверены, телевизор их игнорирует. Это работает только через ADB (`input keyevent 178`, интент `content://android.media.tv/passthrough/<id входа>`).
- **Google Play отключён** прошивкой (`com.android.vending`) и другого магазина нет. Приложения ставятся вручную через `adb install` и только из официальных или проверенных источников; Android проверяет подпись при установке. Так поставлен Prisma; файл TorrServe MatriX 142 Android отклонил (подпись не сходится с содержимым).
- Памяти всего около 940 МБ: телевизор сам выгружает лишнее.
- Включить выключенный (в глубоком сне) телевизор по сети пока нельзя (нужен Wake-on-LAN и его MAC).

## Что проверено, а что нет

Проверено вживую: сопряжение с кодом с экрана, клавиши, состояние, меню источников через «Input», выбор источников, закрытие списка приложений (чтение), запуск Prisma кнопкой.

**Не проверено:** запуск приложений по ссылкам (YouTube, Netflix и др.), стрелки и OK внутри «Source Choice» через сетевой пульт, поведение после ухода телевизора в сон и возврата, кнопка «Close» у конкретных приложений.

## Если что-то не так

- **«Not answering»:** телевизор выключен или спит; включите его пультом. Страница подключится сама.
- **Ответ 404 на новую кнопку:** старый сервер, перезапустите (см. выше).
- **«could not reach the TV over ADB»:** отладка по сети выключена или `adb` не найден (`TV_ADB_PATH`).
- **«the TV has not authorised this computer for ADB»:** подтвердите запрос на экране телевизора.
- **Опечатка в коде сопряжения:** «that is not the code the TV shows»; введите правильный код, начинать заново не нужно.
