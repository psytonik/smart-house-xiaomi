# Roadmap: приложение для камеры psytonik base

## Уже сделано

- Мост go2rtc к Xiaomi PTZ 2K по локальной сети (CS2 P2P), живое видео.
- PTZ через motor-патч для go2rtc (влево, вправо, вверх, вниз).
- Бэкенд на Fastify: токен, PTZ, снимки, прокси видео (WebRTC, HLS, Frames).
- Веб-приложение: живое видео в трёх режимах, джойстик PTZ, снимки.
- Лента CozyLife: включение, яркость, цвет по локальной сети (блок Light strip в вебе).
- Bluetooth-лента Lotus Lantern (ELK-BLEDOM): скрипты `tools/bledom.py`, помощник `tools/ble_helper.py`, запуск из `camera.sh`, обе ленты в одном блоке в вебе (`/api/lights`). Нужно проверить на Mac, см. раздел про Bluetooth.
- Вход в Mi Home и добавление камеры в самом приложении (экран «Cameras», ADR 0013). Не проверено с настоящим аккаунтом.
- Запись по движению: ffmpeg, клипы с запасом до и после, хранение 7 дней, раздел Motion clips в вебе. Проверено на живой камере.

## Сейчас: довести до надёжности

- Проверить HLS после правки `mp4` (fMP4 для H.265). WebRTC уже работает.
- Подобрать `MOTION_THRESHOLD` на реальной сцене (сейчас 1.2).
- Разобраться с потерями пакетов (`cs2: pop buffer is full`): патч go2rtc уже не рвёт соединение (ADR 0015); осталось понаблюдать, найти, что застревает у читателя очереди, и при необходимости снизить битрейт в Xiaomi Home, проверить Wi-Fi камеры, подключить Mac по кабелю.
- Автозапуск go2rtc и бэкенда при старте Mac (launchd).

## Bluetooth-лампы: что осталось сделать

- Восстановить затёртые файлы (`app.ts`, `config.ts`, `App.tsx`, `api.ts`, `styles.css`), потом заново подключить `registerLights` и `Lights`. Без этого тесты и сборка не проходят.
- Один раз выполнить `./camera.sh ble-setup` (venv, bleak, токен помощника), затем запускать `./camera.sh` только из Terminal.app: у Warp нет доступа к Bluetooth (macOS TCC).
- Проверить с живой лентой: помощник поднялся, обе ленты видны в вебе, цвет, яркость и выключение работают.
- Закрывать приложение Lotus Lantern на телефоне: лента держит одно соединение.
- Показать в вебе, что состояние Bluetooth-ленты неизвестно (она только принимает команды), и запоминать последние значения между перезапусками.
- Проверить повторное подключение после сна Mac и после выключения ленты из розетки.
- Закрепить IP Wi-Fi ленты (DHCP-резервирование в роутере): она отвечает как 10.0.0.1.
- Автозапуск помощника вместе с бэкендом (launchd), только через Terminal.app или приложение с доступом к Bluetooth.
- Позже: сцены и расписание («вечер», «ночь») сразу для обеих лент; включение света по событию камеры.

## Шаг 1. Пуш-уведомления в бэкенде

- Эндпоинт регистрации телефона (Expo push token).
- Отправка уведомления, когда готов новый клип: время, длительность, превью.
- Ограничение частоты, чтобы не засыпать частыми событиями.
- Тесты на имитации Expo Push.

## Шаг 2. Мобильное приложение (Expo, React Native)

- Экран входа по токену (хранить в Secure Store).
- Живое видео: WebRTC, запасной вариант Frames.
- Джойстик PTZ и кнопка снимка.
- Список клипов и снимков, просмотр, удаление.
- Получение пушей и переход из уведомления сразу к клипу.

## Шаг 3. Доступ из-за пределов дома

- Tailscale на Mac и на телефоне, бэкенд доступен только внутри VPN.
- HTTPS не нужен внутри VPN. Порт в интернет не открываем.
- Проверить WebRTC через VPN (при необходимости TURN или откат на Frames).

## Потом, по желанию

- События в реальном времени через SSE вместо опроса.
- Запись звука.
- Журнал событий с фильтрами и отметкой часов, зоны движения (маска).
- Место на диске: лимит размера кроме 7 дней.
- Несколько камер.
- Принести motor-патч в основной go2rtc или оформить как свою сборку.

## Риски и ограничения

- Камера держит одну P2P-сессию: пока рекордер подключён, Xiaomi Home видео не покажет.
- Токен Xiaomi лежит в `go2rtc.yaml`, не коммитить и не показывать.
- Motor-команды не входят в официальную спецификацию, после обновления прошивки могут измениться.
- Видео в H.265: на части устройств проигрывается только через WebRTC или аппаратно.
